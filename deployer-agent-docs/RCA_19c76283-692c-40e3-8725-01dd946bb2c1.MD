## Root Cause
A platform-side automated phishing/abuse classifier flagged this deployment and blocked it before rollout. This is a trust-and-safety gate, not a build, manifest, secret, source-code, tier, or infra-capacity failure. The build artifact was fine — the block is independent of app code.

## Why no fix was applied here
- Nothing in the manifest set or app source causes this; a manifest rewrite or source fix cannot clear a phishing classification.
- `resume_pipeline` in the same session would re-enter the identical `AwaitPhishingClassification` gate and be blocked again. The platform's own message instructs forking the session and starting a new deployment.

## Suggested remediation
1. **User:** Fork the session and start a fresh deployment, as instructed by the platform message.
2. **User → Support:** If the app is legitimate (crypto-themed name/content likely tripped the phishing heuristic), file an Emergent support ticket quoting deployment `c00f34e1-af72-4be6-bb64-43844dd82c8f` and run `19c76283-692c-40e3-8725-01dd946bb2c1` to have the phishing classification reviewed/cleared.

## Impact
The live site is NOT down — the previous successful run (`e32451f9...`) remains active and continues to serve traffic. Only the new redeploy was blocked.
